# WAR-032~042 구현·검증 기록

검증 날짜: 2026-09-09. Unity 2021.3.45f2, Windows Editor, Android IL2CPP.

## 콘텐츠 가져오기 (WAR-040)

진입점: `Tools > Update All Game Data`.

1. ItemData, StatusData, NodeData를 순서대로 비동기 요청한다. 요청별 제한 시간은 30초다.
2. 세 응답을 모두 메모리에 확보한 뒤 JSON 파싱·검증한다. 다운로드 중에는 에셋을 쓰지 않는다.
3. 빈 시트, 잘못된 ID, 중복 ID, 타입 교체, 누락된 링크·적·아이템·이벤트를 거부한다.
4. 건수 미리보기에서 적용 또는 취소한다. 현재 미리보기는 필드별 diff가 아닌 갱신 건수다.
5. 기존 에셋을 수정한다. 타입 교체를 위한 삭제·재생성을 금지해 기존 GUID를 보존한다.

실제 온라인 시트 적용은 콘텐츠를 덮어쓰므로 검증 과정에서 실행하지 않았다.
검증 실패/네트워크 실패는 쓰기 전 중단한다. 적용은 하나의 Undo 그룹으로 묶고 예외 시 되돌리기를 시도한다. 다만 디스크 장애에 대한 파일 단위 트랜잭션은 제공하지 않는다. Undo/Redo 실동작 검증은 아직 남아 있다.
적용 전 Git 변경을 확인하고, 예상하지 못한 변경은 커밋하지 않는다.

## 콘텐츠 검사 (WAR-041)

진입점: `Tools > Validate Game Data`. 모든 빌드의 전처리에서도 같은 검사를 수행한다.

- Resources/Nodes: 실제 노드 타입, 다음 노드, 전투 성공/실패 링크, 적, 선택지, 필수 이벤트.
- Resources/Items: ID 누락·중복, 파일명과 ID 불일치.
- Resources/Characters: 드롭 확률이 있으나 아이템 참조가 없는 설정.
- 오류 메시지에 해당 에셋 경로와 선택지 인덱스를 포함한다.
- 검사기는 콘텐츠를 수정하지 않으며 오류가 있으면 빌드를 실패시킨다.

확인된 결과:

- Unity 에디터 컴파일 오류 0건.
- 현재 Resources 콘텐츠 검사 오류 0건.
- 빈 문자열, 객체 JSON, 빈 배열, HTML 응답 거부: 4/4 통과.
- 임시 CombatNode의 적·성공·실패 참조 누락 3건을 모두 검출했다. 테스트 객체는 메모리에만 만들고 종료 시 제거했다.
- 정상 최소 스냅샷 검증 통과, 중복 아이템 ID 거부 통과. 실제 에셋 적용 없이 메모리 JSON으로 검사했다.

## 모바일 검증 (WAR-032)

기존 UI는 1080×1920 기준의 Screen Space Camera Canvas를 사용한다.
CameraResolution은 9:16 레터박스를 화면 크기가 바뀔 때 다시 계산하도록 수정했다.
CanvasSafeArea는 화면 카메라 영역과 Screen.safeArea의 교집합으로 UI 컨테이너를 조정한다. 초기 자식들의 앵커·오프셋은 유지한다.
MCP 재연결 후 MainWindow의 MainUI_Canvas와 GameWindow의 UICanvas에 연결했다. 기존 씬의 미저장 변경이 없음을 먼저 확인했다.

수동 진입점은 `Tools > Mobile UI > Add Safe Area to Selected Canvas`이며, 변경 후 씬 저장이 필요하다.
`Tools > Mobile UI > Run Safe Area Math Checks`의 전체 화면·인셋·레터박스·초기 해상도 4종은 실행하여 모두 통과했다.
Play Mode에서 메인 컨테이너의 자식 6개, 새 게임 진입 후 게임 컨테이너의 자식 3개와 전체 화면 앵커를 확인했다. Console 오류 0건. 자동 저장을 끈 뒤 시작하여 사용자 저장 파일을 쓰지 않았다.
이 결과는 구조/기본 실행 검증이며 화면 이미지 판독이나 실제 터치·기기 검증을 대신하지 않는다.
추가로 메인 화면 캡처에서 제목·버튼 배치를 확인했다. Game View 원본 캡처에서는 날짜/지역/체력 HUD 표시를 확인했다. 카메라 단독 캡처는 UI가 빠진 검은 화면을 반환했으므로 실제 Game View 증거로 사용하지 않았다.
캡처 파일은 Git에서 제외된 `Builds/Validation/`에 있다. 문구 전체 타이핑·선택·인벤토리·전투·엔딩을 모두 시각 검증한 것은 아니다.
`adb devices -l` 결과 연결 기기가 없었다.

## 추가 회귀 수정

Play Mode 종료 시 CombatManager.OnDestroy에서 CharacterManager.Instance를 다시 조회하면서 이미 파괴된 매니저를 찾는 오류를 확인했다.
Awake에서 구독한 CharacterManager 참조를 보관하고 같은 객체에서 해제하도록 수정했다. 수정 후 새 게임 진입 및 Play Mode 종료의 Console 오류는 0건이었다.
안전 영역 재부모화 시 RectTransform의 anchoredPosition3D와 sizeDelta를 명시적으로 보존했다.
안전 영역은 배경을 포함한 Canvas의 기존 자식 전체에 적용되므로 실제 화면의 배경 가장자리도 확인한다.
실제 기기의 노치/제스처 영역, 화면 회전, 터치 영역, 한글 가독성 검증은 아직 완료되지 않았다.
