# 아이템 장비 슬롯·저장 복원 수정 내역

작성일: 2026-09-16

## 범위와 기준 상태

- 사용자가 수정한 `ArmorItem[] armorItem` 구조를 유지하고 저장·복원 경로를 연결했다.
- 기준 커밋: `af613f0`, 브랜치: `codex/war-001-to-042`.
- 작업 시작 시 사용자 수정 파일 6개가 있었으며 해당 변경을 보존했다.
- Unity 2021.3.45f2, Android 타깃, `GameWindow` 씬의 Edit Mode에서 확인했다.
- 초기 콘솔에는 SaveManager의 `string[] -> string`, `ArmorItem[] -> BaseItem` 형 변환 컴파일 오류 2개가 있었다.

## 원인과 수정

| 부분 | 확인한 문제 | 수정 |
| --- | --- | --- |
| 장비 저장·복원 | 방어구를 배열로 바꾼 뒤에도 단일 ID/단일 아이템으로 처리 | 4개 ID 슬롯을 각각 저장하고 타입과 슬롯을 검증해 복원 |
| 방어구 해제 | 하나를 해제하면서 배열 전체를 null로 변경 | 실제 장착된 아이템의 해당 슬롯만 비움 |
| 장비 데이터 복사 | 배열 참조를 공유하여 스냅샷 수정이 플레이어에 전파 | 배열 컨테이너 복사, null·짧은 배열 초기화 |
| 소모품 저장 | ID만 기록하여 수량 누락 | `inventoryItems`에 `itemId`, `quantity` 기록 |
| 소모품 상태 | 원본 ScriptableObject의 quantity를 직접 변경 | 인벤토리별 런타임 복사본 생성, 제거·새 게임·매니저 파괴 시 정리 |
| 소모품 합산 | 참조 비교로 로드된 복사본과 원본을 다른 스택으로 취급 | ID 기준 스택 합산, 드롭 1회당 1개 획득 |
| 인벤토리 상한 | 재초기화 시 가득 참 상태가 남음 | 새 게임·로드·추가·제거 시 슬롯 개수로 다시 계산 |
| 무기 사거리 | 장비 계산 시 rangeBonus를 0으로 초기화하고 미반영 | 무기의 range를 반영 |
| 잘못된 저장 내용 | 없는 아이템을 건너뛰어 일부만 복원 | 누락 ID·타입/부위 불일치·잘못된 수량은 오류로 반환, 부분 결과 전달 안 함 |

## 슬롯 규칙

기존 에셋에 저장된 enum 번호를 바꾸지 않았다.

| 배열 인덱스 | ArmorType | 부위 |
| --- | --- | --- |
| 0 | Helmet | 머리 |
| 1 | Chestplate | 몸통 |
| 2 | Boots | 신발 |
| 3 | Gloves | 장갑 |

배열 접근은 `equipmentData.armorItem[(int)ArmorType.Gloves]`처럼 enum을 사용한다.
UI에서 장갑을 신발보다 먼저 보여 주더라도 저장 번호를 재정렬하지 않는다.

## 저장 형식 v3와 호환 정책

- 현재 버전은 `3.0f`이다. 새 방어구 ID 배열 이름은 `armorItemIds`이다.
- 구 `armorItemId` 문자열과 새 배열을 다른 이름으로 분리해 타입 충돌을 피했다.
- v1/v2의 단일 방어구는 로드한 에셋의 `armorType` 위치로 옮긴다.
- v1의 플레이어 성향 이전과 v2의 Player 성향 저장 방식은 유지한다.
- 구 `inventoryItemIds`에는 수량이 없으므로 ID 등장 횟수만큼 복원한다. 보통 소모품 ID가 한 번만 기록되어 1개가 된다. 기록되지 않은 과거 실제 수량은 추정하지 않는다.
- 새 파일의 소모품 수량은 양수만 허용한다. 저장 시 이미 0개인 스택은 제외한다.
- 장비의 인벤토리 항목은 항목당 quantity 1이다. 같은 소모품 ID가 반복되면 안전하게 합산하며 정수 범위를 넘으면 실패한다.
- 무기·장신구는 기존 단일 ID 구조를 유지한다.
- 이전은 메모리에서 수행한다. 성공적으로 불러온 뒤 게임의 정상 저장 시 v3로 기록한다. 검사만으로 원본 세이브를 덮어쓰지 않는다.
- `ItemData.consumableQuantities`는 로드 결과를 InventoryManager로 전달하기 위한 일시적인 수량 표다. 초기화 후 실제 수량의 주인은 `InventoryManager.inventoryItems`의 소모품 복사본이다.

## 주요 변경 파일

- `EquipmentData.cs`, `Player.cs`, `EquipmentItem.cs`: 슬롯 초기화·복사·장착·해제·스탯.
- `SaveGameData.cs`, `SaveManager.cs`: v3 DTO, 구 버전 이전, ID/수량 저장 및 복원 검증.
- `ItemData.cs`, `ConsumableItem.cs`, `InventoryManager.cs`: 수량 전달과 런타임 복사본 소유·정리.
- `Assets/Editor/ItemSaveValidation.cs`: 이번 변경의 자동 회귀 검사.
- `Assets/Editor/CharacterRefactorValidation.cs`: 저장 버전 검사를 현재 버전에 맞춰 갱신.

## 검증 결과

- Unity 스크립트 컴파일 완료, 최종 콘솔 오류 0개 / 경고 0개.
- `ItemSaveValidation.RunChecks()`: 51개 항목 통과.
  - 4부위 합산, 동일 부위 재장착·교체, 반복 해제, 배열 복사 격리.
  - 무기·장신구·방어구 왕복 및 HP 보존.
  - 임시 경로에서 실제 파일 신규 생성·원자적 교체·TryLoadGame 읽기.
  - 수량 복원, 반복 로드, 로드 후 추가·사용·재저장, 마지막 1개 사용 후 제거.
  - 20슬롯 상한, 가득 찬 상태에서 기존 스택 추가, 새 게임·빈 데이터 복원.
  - v1/v2 단일 방어구 이전, 구 소모품 ID 합산, v3 재저장.
  - 손상 JSON, 잘못된 슬롯 수, 누락 아이템, 다른 부위/타입, 음수·0 수량 거부.
  - 프로젝트의 실제 Resources 아이템 로드.
- `CharacterRefactorValidation.RunChecks()`: 기존 26개 항목 통과.
- `GameDataValidator.ValidateAll()`: 오류 0개.
- 테스트는 Unity Test Framework 스위트가 아닌, 에디터 메뉴에서 실행하는 회귀 검사다.
- 검사용 소모품과 네 부위 장비는 임시 메모리 객체로 생성했다. 실제 에셋·씬·프리팹·사용자 savedata.json은 수정하지 않았다.
- 컴파일 도중 MCP 재접속 경고가 잠시 발생했으나 재연결 후 최종 검사에서는 오류·경고가 없었다.

재실행 메뉴: `Tools > Validation > Item Save and Armor Slots` 및 `Character and Save Refactor`.

## 제한과 후속 확인

- Play Mode의 전체 화면 조작·씬 전환, Android 빌드/기기 저장 경로 검증은 이번에 실행하지 않았다.
- 실제 콘텐츠 소모품을 추가할 때 `Resources/Items/{itemID}` 경로와 고유 ID, `isConsumable`, 효과 수치를 설정해야 한다.
- 장비는 기존처럼 정의 에셋을 공유한다. 앞으로 개별 장비의 내구도 감소·강화·랜덤 옵션을 구현한다면 장비 인스턴스 ID와 상태 저장 형식을 추가해야 한다. 이번 범위는 방어구 슬롯과 소모품 수량이다.
- 기존 원자적 파일 교체는 유지했으며, 별도 백업 세이브 복구 기능은 추가하지 않았다.
- 사용자가 작성한 장비 UI 갱신 주석은 유지했다. 실제 인벤토리/장비 UI 갱신 기능 전체를 새로 구현한 작업은 아니다.
