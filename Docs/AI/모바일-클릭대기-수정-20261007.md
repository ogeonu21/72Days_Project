# 모바일 대화 클릭 대기 수정

## 원인과 변경

기존 `WaitForClick.WaitClick()`은 `touchCount > 0`이면 즉시 끝났다. 따라서 새 터치가 아니라 길게 누르기·이동·종료 프레임도 확인 입력이 됐다. 마우스도 대기 시작 프레임의 Down을 재사용할 수 있었다.

공통 함수를 아래 순서로 변경했다.

1. 대기 시작 당시의 모든 터치가 사라질 때까지 기다림.
2. 해제/시작 프레임을 넘김.
3. 이후의 `TouchPhase.Began`만 확인 입력으로 인정.

모바일에서는 터치에서 합성된 마우스 입력을 사용하지 않는다. PC/에디터는 새 왼쪽 마우스 클릭을 지원한다. 이벤트 결과창에만 있던 중복 해제 대기는 제거하고 공통 함수에 위임했다. 전투·보상·메인 스토리·엔딩도 같은 함수로 동작한다. 일반 Story 선택지 표시는 기존대로 본문 완료 후 나온다.

## 검증 범위

`Tools/Validation/Wait For Click` 검사를 추가했다. 무입력, 길게 누르기 120프레임, 잔여 접촉, 입력 해제, 새 입력 아닌 접촉, 다음 대기 재진입, 시작 프레임 마우스 입력을 검사한다.

Unity MCP가 `no_unity_session`을 반환하여 이번에는 실제 Unity 컴파일/실행 검증을 수행하지 못했다. 엔진 API 대역을 사용하는 별도 C# 검사로 실제 수정 소스와 검사 코드를 실행했다. 이 검사는 코루틴 로직을 확인하며 기기 입력 검증을 대신하지 않는다.

모바일 확인 절차: 본문 타이핑 중 화면을 길게 누름 → 본문 완료 후에도 대기 유지 → 손만 떼면 대기 유지 → 다시 터치하면 한 번 진행. 전투 연속 공격 메시지와 보상 메시지에서도 반복한다. 실제 씬·세이브 데이터는 수정하지 않았다.
