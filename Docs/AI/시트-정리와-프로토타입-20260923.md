# 시트 정리 및 프로토타입 데이터

## 실제 반영 내용

- NodeData, ItemData, StatusData의 헤더·본문 서식, 줄바꿈, 필터, 헤더 고정을 통일했다. 종류 필드는 드롭다운, Consumable은 체크박스로 설정했다.
- 기존 연동 호환성을 위해 헤더 위치는 유지했다: NodeData 2행, StatusData 3행, ItemData C3부터. 모든 시트의 헤더를 같은 행으로 옮긴 것은 아니다.
- 빈 숫자 값을 0으로, 사용하지 않는 참조 값은 빈 문자열로 정리했다. 확률과 회피 보너스는 소수로 유지한다(0.1 = 10%).
- 기존 ID·연결·밸런스 수치는 유지했다. Accessory_01의 미사용 QuestID 0은 빈 값으로 정리했다.
- Event_01의 확률 설명, Event_02의 보상·소비 설명을 현재 코드 동작에 맞췄다. 오타와 불필요한 공백을 정리했다.
- ItemData A1:A10의 장식용 세로 병합을 해제해 3행 헤더 고정이 가능하도록 했다. 데이터 열은 이동하지 않았다.

## 추가 데이터와 흐름

전체 데이터: 노드 18개, 아이템 11개, 적 7개, 이벤트 12개, 이벤트 선택지 18개, 보상 항목 17개.

추가된 Proto_ 데이터: 노드 9개, 아이템 2개, 적 1개, 이벤트 4개, 선택지 5개, 보상 항목 6개.

Proto_Start → 보급 → 갈림길 → 상점 또는 조우 → 전투 또는 회피 → 휴식 → 종료.

- 보급: 100골드, 연습용 몽둥이 1개, 응급 물약 2개.
- 상점: 응급 물약을 20골드에 반복 구매. 떠나면 갈림길로 복귀.
- 전투: Proto_Enemy와 전투. 승리 시 휴식, 패배 시 실패 엔딩. 드롭은 물약 1개와 30골드.
- 휴식: 체력 25 회복, 경험치 10 획득.
- 갈림길에서 전투 없이 종료하는 경로도 제공한다.

## 실행 방법

1. 기존 작업과 저장 데이터를 백업한다.
2. DataImporter로 여섯 시트의 데이터를 가져온다. 이번 작업에서 Unity 에셋 가져오기는 실행하지 않았다.
3. 현재 게임 시작은 Main_01로 고정되어 있다. 프로토타입을 시험하려면 시트에서 Main_01의 NextNode를 잠시 Proto_Start로 변경하고 다시 가져온 뒤 새 게임을 시작한다.
4. 보급 후 인벤토리에서 몽둥이를 장착하고 물약 수량, 구매, 전투, 회복을 확인한다.
5. 테스트 후 Main_01.NextNode를 Main_02로 복구하고 다시 가져온다.

## 검증과 제한

- 실제 시트를 다시 읽어 여섯 시트의 헤더와 모든 작성 값이 계획 데이터와 일치하는지 확인했다.
- Proto_Start에서 신규 노드 9개 전체에 도달하는 연결 구조를 확인했다.
- Unity 실행 검증은 도구의 사용량 제한으로 수행하지 못했다. Play Mode, 실제 저장 파일, 기존 Unity 에셋은 변경하지 않았다. 전투 난이도가 검증된 데이터는 아니다.
- 기존 Combat_02.FailureNode가 승리 엔딩 Ending_01을 가리키는 설정은 의도 확인이 필요해 유지했다.
