# 공통 선택지 UI와 전투 행동

## 구조

```text
ChoiceUIRouter (추상 MonoBehaviour)
├─ EventUIRouter  : 이벤트 조건·보상·결과 문구 연결
└─ CombatUIRouter : 공격·아이템·도주 메뉴와 하위 목록

CombatUIRouter → CombatManager.TrySubmitInput → 기존 전투 코루틴
```

- 부모는 패널, 스크롤 목록, 버튼 템플릿 복제, 라벨, 입력 리스너와 숨김 처리를 담당한다.
- 부모는 EventNode나 CombatNode를 모르며 보상·아이템 사용·노드 이동 규칙을 소유하지 않는다.
- 자식은 표시할 목록과 클릭했을 때 수행할 행동을 정의한다.
- 기존 ChoiceListPresenter는 고정된 Story 버튼을 위한 별도 구성으로 유지한다. 이번 변경은 Story UI까지 전면 교체하지 않는다.

## 전투 화면

| 선택 | 동작 | 턴 |
| --- | --- | --- |
| 공격 | 기존 인체 그림에서 부위 버튼 직접 클릭, 피격률·데미지 범위 유지 | 기존 사거리 기반 선후공과 양측 공격 유지 |
| 아이템 사용 | 소지 소모품을 이름 ×수량으로 표시 | 사용 성공 시 1개 소비·효과 적용 후 적 1회 공격 |
| 도주 성공 | 승리 후 이동 노드인 CombatNode.successNode로 이동 | 보상 없음, 적 반격 없음 |
| 도주 실패 | 실패 문구 표시 | 적 1회 공격 |
| 뒤로 | 상위 행동 목록 복귀 | 소비 없음 |

아이템은 선택 시점에 실제 인벤토리 객체를 재확인한다. 체력이 가득 찬 회복 물약, 이미 사라진 아이템, 수량이 없는 아이템은 소비하지 않는다. 입력 수락 즉시 턴을 잠가 중복 소비를 막는다. 일반 인벤토리의 소모품 사용은 전투 중 차단하고 전투 메뉴를 이용하도록 안내한다. 장비 변경 규칙은 이번 작업에서 변경하지 않았다.

상태 효과의 적용·카운트 시점과 공격의 선후공 계산은 기존 CombatLoop의 규칙을 유지한다. 아이템 사용과 도주 시도는 적의 공격보다 먼저 처리한다.

## 설정과 연결

- `CombatManager > Escape Probability`: 기본 0.5(50%). 0은 항상 실패, 1은 항상 성공이다.
- successNode가 없거나 자기 자신을 가리키면 도주 버튼을 비활성화한다.
- `CombatUIController.attackButtons`와 `combatText`의 기존 씬 연결을 재사용한다.
- 기존 인체 그림·부위 버튼·피격률·데미지 범위를 유지한다. 부위 버튼은 행동 처리 중에만 interactable=false로 잠그며 숨기지 않는다.
- 추가 선택지는 인체 영역 아래 남은 공간에 별도 패널로 표시한다. 최상위 목록은 아이템 사용·도주 두 개이고, 아이템 목록에는 뒤로가 있다.
- 선택지 모양은 같은 Canvas의 EventUIController.choiceButtons[0]을 재사용한다. 다른 화면에서는 CombatUIController의 Choice Template에 TMP 라벨이 있는 버튼을 지정한다.
- 기존 `AttackAreaInput(int)` 메서드를 유지하므로 이전 버튼의 정수 인자 연결도 유효하다.
- 선택지는 ‘무슨 행동을 할 것인가?’ 본문 출력이 끝난 뒤에 열리고, 행동 처리 중에는 숨긴다.
- UI가 닫히거나 다른 전투로 전환되면 진행 중 코루틴·사망 이벤트 구독·입력을 정리한다.
- Node SO, Item SO, Character SO 및 DataImporter·구글 시트 열은 변경하지 않았다. 도주율은 현재 매니저 공통 설정이며 노드별 값은 아니다.

## 다른 노드에서 확장하기

`ChoiceUIRouter`를 상속하고 다음 API를 사용한다.

1. `OpenChoices(key, buttonTemplate, font)`: 패널을 열고 템플릿을 지정한다. 실패하면 진행하지 않는다.
2. `NewContent()`: 이전 목록을 정리하고 새 목록의 부모 Transform을 반환한다.
3. `AddChoice(content, label, callback, available)`: 선택지를 추가한다. available=false이면 비활성 버튼이 된다.
4. 하위 메뉴 콜백에서 NewContent와 AddChoice를 다시 호출한다. ‘뒤로’도 일반 콜백으로 구성한다.
5. `HideChoices()`: 선택지를 숨기고 이전 목록의 클릭을 무효화한다.
6. 필요하면 PanelAnchorMin/PanelAnchorMax 또는 ChoicePanelParent/LayoutPanel을 재정의한다. 전투는 인체 영역의 형제로 패널을 만들고 아래 빈 공간의 높이를 계산한다.

OnDisable을 재정의할 경우 부모의 숨김 처리 또는 HideChoices를 호출하고 자식이 등록한 외부 이벤트도 해제한다. 기존 EventUIRouter의 조건 미충족 선택지 숨김·성공/실패 문구·클릭 대기 정책은 유지했다.

## 검증 결과와 한계

- Unity 2021.3.45f2의 GameWindow에서 새 코드 컴파일 및 실행 가능한 타입 확인.
- Combat Choices 25개 통과: 상속, 확률 경계, 중복 입력, 잘못된 입력, 소비·회복, 수량 표시, 마지막 수량 제거, 빈 목록, 뒤로, 이전 목록 클릭 차단, 취소·반복 구성.
- 기존 Combat Attack 11개, Event Probability 14개 통과.
- GameWindow의 attackButtons 연결, 버튼 템플릿 6개, combatText 연결을 읽기 전용으로 확인.
- UTF-8 검사 통과. 실제 씬·세이브 저장 및 Play Mode 실행은 하지 않았다.
- 실제 전투 코루틴 전체, 도주 후 노드 전환·무보상, 화면 배치·터치 조작은 Play Mode에서 추가 확인이 필요하다. Edit Mode 검사 통과만으로 이러한 실행 검증까지 완료했다고 보지 않는다.

수동 확인 순서: 전투 진입 → 인체 그림의 부위 직접 클릭 → 양측 공격 → 하단 선택지에서 소모품 사용·수량 감소·적 반격 → 도주율 0에서 실패·적 반격 → 도주율 1에서 successNode 이동·보상 없음. 확인 후 원하는 도주율로 되돌린다.

### 인체 공격 UI 복원 후 재검증

- 공격을 일반 선택지 목록으로 바꾸는 처리를 제거했다. 인체 그림과 부위별 기존 수치·Inspector 클릭 연결을 유지한다.
- 기존 부위 버튼은 숨기지 않고 입력 가능 여부만 턴에 맞춰 갱신한다.
- 하단 추가 목록은 아이템 사용·도주만 포함한다. 아이템 목록을 열어도 인체 공격 영역은 유지된다.
- GameWindow를 Edit Mode에서 추가로 열어 읽은 뒤 저장하지 않고 닫았다. 부위 버튼 6개, 수치 라벨 6개, 이벤트 템플릿 1개, 인체 아래 여유 공간 600(UI 좌표)을 확인했다.
- 변경된 Combat Choices 25개 및 Combat Attack 11개 통과, Console 오류 0개. Play Mode와 실제 해상도별 시각 검증은 별도다.

### 본문과 추가 선택지 영역 분리

인체 아래 공간에 본문도 배치되어 있어 추가 선택지가 겹치는 문제를 수정했다. 이제 위에서부터 인체 → 전투 본문 → 16의 여백 → 추가 선택지 순서다. 아래 공간의 약 45%를 선택지에 할당하고 나머지를 본문에 사용한다. 목록은 해당 영역 안에서 스크롤되며 본문은 24~48 크기로 자동 조절하고 영역 밖 렌더링을 마스킹한다. 매우 긴 문구는 최소 글자 크기에서도 잘릴 수 있으므로 별도 스크롤 본문 확장은 후속 검토 대상이다.

GameWindow의 Edit Mode 좌표 검사 결과: 본문 높이 약 318.2, 선택지 높이 241.8, 사이 여백 약 16. 씬을 저장하지 않고 실제 RectTransform 계산을 검사했다. Combat Choices 26개 통과, 검사 시 콘솔 오류 0개. Play Mode 시각 검증은 하지 않았다.
