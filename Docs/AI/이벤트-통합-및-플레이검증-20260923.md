# 이벤트 시스템 통합 및 플레이 검증

## 적용 결과

2026-09-23, 기존 이벤트 실행 경로를 제거하고 EventDefinition 방식으로 통합했다. 시트와 Unity Resources 에셋에 모두 적용했다.

- 구형 MeetingEvent.Execute에서 무시하기 선택도 `who.enemyData`를 읽어 NullReferenceException이 발생했다. 해당 실행 클래스와 폴백 호출을 제거했다.
- BaseEvent, IEvent, MeetingEvent, StatUpdateEvent, MeetingEventEditor, 구형 이벤트 에셋 6개, 임시 이동용 DumpNode를 제거했다.
- EventNode는 EventDefinition만 참조한다. 정의가 없는 이벤트는 임포트·콘텐츠 검사에서 오류로 처리한다.
- 구형 이벤트가 공유 CombatNode의 성공 노드를 런타임에 덮어쓰던 경로를 제거했다. 이동은 시트에 지정한 전투 노드와 성공·실패 연결을 사용한다.
- 레벨업 버튼 3개를 `ApplyLevelUpStat(str/dex/con)`으로 전환했다. 레벨업은 해당 능력치 +1만 적용하며 노드를 임의로 이동하지 않는다. 이벤트 훈련소의 STR +10 설정은 유지했다.
- Combat_02의 패배 연결을 승리 엔딩이 아닌 Ending_02로 수정했다.

## 선택지 조건

조건은 모두 AND이며, 하나라도 부족하면 버튼을 비활성화하고 `[잠김]`과 부족한 조건·현재 값을 표시한다. 선택지는 숨기지 않는다. 이미 처리한 단발 선택지와 중복 퀘스트 수락·완료도 비활성화한다.

골드·인벤토리·스탯·성향·퀘스트 진행 변경을 관찰해 현재 화면의 버튼을 갱신한다. 버튼 클릭 시 같은 판정기를 다시 호출하므로 표시 이후 조건이 바뀌어도 보상이나 비용을 우회 처리하지 않는다. 본문 타이핑이 끝난 뒤 선택지를 표시하는 규칙은 유지했다.

이 조건은 **EventChoiceData의 이벤트 선택지**에 적용한다. StoryNode의 간단한 이동 선택지는 기존 NodeData에서 관리하며 무조건 이동한다. 조건부 갈림길은 EventNode로 작성한다.

| 열 | 규칙 |
| --- | --- |
| RequiredQuestID | 조건으로 검사할 퀘스트 ID. 빈 값이면 퀘스트 조건 없음 |
| RequiredQuestState | Active: 수락 후 미완료 / Completed: 완료 / NotAccepted: 미수락 / Accepted: 수락 이력(완료 포함) |
| RequiredItemID, RequiredQuantity | 해당 ID의 인벤토리 수량 합계. 장비도 인벤토리에 있으면 포함. 보유 확인만 하며 소비하지 않음 |
| RequiredGold | 최소 보유 골드. 소비하지 않음 |
| GoldCost | 실제 소비 비용. 조건 판정에서도 잔액 확인. RequiredGold와 합산하지 않고 두 값 중 큰 금액 이상이어야 함 |
| RequiredSTR, RequiredDEX, RequiredCON | 기본 능력치 각각의 최솟값. 0이면 제한 없음. 장비 공격력/체력 보너스와는 별개 |
| TendencyCondition | Any: 제한 없음 / AtLeast: 최솟값 이상 / AtMost: 최댓값 이하 / Between: 양 끝을 포함하는 범위 |
| TendencyMin, TendencyMax | 해당 비교에 사용하는 정수. 0도 실제 조건 값. 최소가 최대보다 큰 범위는 임포트 거부 |
| Repeatable | TRUE인 선택지는 반복 실행 가능하지만 매번 조건·비용을 다시 검사 |

성향은 플레이어의 기존 tendency 정수를 사용한다. 이번 시나리오는 **양수=선행, 음수=악행, 0=중립**으로 작성했다. RewardData에 Kind=Tendency를 추가했으며 Amount에 양수·음수 모두 지정할 수 있다. 다른 보상 종류는 기존처럼 양수만 허용한다.

## 시트 변경

- NodeData: A2:Q31, 노드 29개. EventCategory와 Choice1/2/3_EventName 열을 제거했다. 다른 영역을 이동하지 않도록 기존 데이터 블록을 정리했고 R:U는 비워 두었다.
- EventData: A3:D20, 정의 17개.
- EventChoiceData: A3:V58, 선택지 55개. O:V에 RequiredQuestState, TendencyCondition, TendencyMin, TendencyMax, RequiredGold, RequiredSTR, RequiredDEX, RequiredCON을 추가했다.
- RewardData: A3:F29, 보상 항목 26개. Tendency 보상 추가.
- ItemData 11개, StatusData 7개는 이번 전환에서 시트 값을 변경하지 않았다.
- 헤더 행은 유지했다. 기존 Apps Script 주소로 여섯 시트를 실제 읽어 검증했으므로 재배포는 필요하지 않았다.
- 이후 시트 변경 시 `Tools > Validate Remote Game Data (No Changes)` 검사 후 `Tools > Update All Game Data`를 적용한다.

## 새 게임에서 확인하는 순서

현재 시작 노드 Main_01을 유지한 상태로 아래 검증 경로가 연결되어 있다. 오래된 저장에서는 이미 선택한 단발 보상·완료 퀘스트가 잠겨 있을 수 있으므로, **기존 저장을 별도 보관하고 새 게임으로 검증**한다. 기존 저장 파일은 이번 작업에서 변경하지 않았다.

1. Main_01 → Main_02 → Main_03: 메인 스토리 타이핑과 일반 Story 선택지를 확인한다.
2. `보급로와 전체 이벤트 검증` → Proto_Start → Proto_Supply: 보급품을 수령한다. 100골드, 몽둥이 1개, 응급 물약 2개를 확인하고 몽둥이를 장착한다.
3. Proto_Hub → QA_Quest: 완료 보고가 잠겨 있고 사유가 표시되는지 확인한다. 의뢰를 수락하면 수락 버튼은 잠기고, 완료 버튼은 스탯·성향 조건이 부족해 계속 잠겨 있어야 한다.
4. 떠나기 → Proto_Hub → 전체 검증 목록(QA_Hub) → 훈련소(Event_01): STR +10, DEX +1, CON +1을 각각 받는다. 다시 누르면 재수령되지 않아야 한다. 떠나기로 Main_03에 복귀한다.
5. Main_03 → 보급로: 이미 받은 보급은 잠겨 있지만 떠나기로 계속 진행할 수 있다. QA_Hub → Event_02에서 도와주기를 선택하면 성향 +1. 현재 의뢰 조건이 충족된다.
6. QA_Quest에서 완료 보고: 골드 +50, 경험치 +10을 확인한다. 완료·수락은 다시 실행할 수 없어야 하며, 완료자 전용 이동 선택지가 활성화되어야 한다.
7. QA_Conditions: 물약 3개와 골드 150 조건은 아직 부족하다. 떠나기 후 Proto_Shop에서 물약 1개 구매하면 보유 물약 3개, 골드 130이 된다. QA_Demo_Gold에서 100골드를 받으면 골드 230으로 조건을 충족한다.
8. QA_Conditions 재방문: 모든 조건 선택지가 활성화되는지 확인한다. 개발용 성향 +1/-1로 0, 1, -1의 경계를 오가며 중립·선행·악행 선택지 상태를 확인한다. 단발 확인 버튼은 한 번 실행하면 수령 완료로 잠기므로, 조건 변화만 볼 때는 누르지 않고 관찰한다.
9. 인벤토리에서 물약을 버려 2개로 만들면 아이템 조건이 다시 잠겨야 한다. 충분한 골드가 있으면 상점에서 다시 구매해 복구한다. 보유 확인 선택지는 아이템이나 골드를 소비하지 않는다.
10. 모든 조건 충족 선택지 → Proto_Encounter → 전투 → Proto_Combat: 승리 시 Proto_Rest, 패배 시 Proto_Fail. 회피 선택지도 Proto_Rest로 연결된다. 휴식하면 실제 체력 회복(최대치 제한)과 경험치 +10을 확인하고 Proto_Finish로 이동한다.

레벨업 창이 뜨면 능력치 하나를 선택해 닫은 뒤 계속 진행한다. 조건 검사에 쓰이는 기본 스탯이 올라가는 것이 정상이다.

## 검증 결과 및 한계

- 주요 구현 적용 후 Unity 컴파일 오류 없음. 아래 207개 검사도 이 시점에 통과했다. 마지막 DumpNode 참조 제거 및 EventUIController 방어 코드 정리 후 재컴파일을 요청했으나 Unity MCP가 응답하지 않아, 최종 정리본의 컴파일 완료 재확인은 남아 있다. 에디터 로그에서 확인된 EventUIController 줄바꿈 혼용은 UTF-8을 유지하며 LF로 통일했다.
- 이벤트 조건 34개, 이벤트/보상/저장 14개, 본문·선택지 표시 순서 20개, 임포터 39개 통과.
- 전투 11개, 아이템/저장 51개, 캐릭터/저장 27개, 스탯 UI 11개 회귀 검사 통과. 합계 207개.
- 실제 Resources의 29개 노드 모두 Main_01에서 연결상 도달 가능. 콘텐츠 연결 오류 0개.
- GameWindow 씬의 누락 스크립트 0개. 레벨업 str/dex/con 버튼 대상 3개 및 이벤트 본문·버튼 템플릿 연결 확인.
- 실제 시트 작성 값을 재조회해 계획 데이터와 전부 일치하는지 확인. 기존 원격 연동을 통한 여섯 시트 검사 통과.
- 이전 요청의 Edit Mode 제한을 유지했다. 이번 작업에서 Play Mode 실제 클릭·전투·화면 크기 검증 및 Android 빌드는 실행하지 않았다. 자동 검사 통과를 실제 전체 플레이 완료로 해석하면 안 된다.
