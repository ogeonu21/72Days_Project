# Story·Event 본문 완료 후 선택지 표시

작성일: 2026-09-22

## 증상과 원인

- 기존 코드는 본문 출력 완료 후 선택지 텍스트를 넣으면서, 최초 진입이나 같은 UI 재사용 시 출력 시작 전에 기존 버튼을 숨기지 않았다. 따라서 빈 버튼 또는 이전 선택지가 먼저 보일 수 있었다.
- 선택지 라벨 검색은 비활성 자식을 제외했다. 임시 UI 실험에서 비활성 라벨은 기존 검색으로 찾지 못하고, 비활성 포함 검색으로 찾는 것을 확인했다. 실제 보고된 증상의 모든 원인이 라벨 비활성 때문이라고 단정하지는 않는다.
- 각 화면의 본문을 전역 코루틴 이벤트에 맡기고, 본문 타이핑을 별도 코루틴으로 시작하여 화면 전환 시 취소 책임이 분리되어 있었다.

## 변경 구조

1. Story·Event UI 활성화 및 본문 출력 시작 시 선택지를 숨기고 이전 리스너를 제거한다.
2. 해당 컨트롤러의 NodeText에 직접 본문을 출력한다.
3. 본문 코루틴이 끝나면 선택지 라벨을 채운 뒤 버튼을 표시한다.
4. 새 노드로 갱신하거나 컨트롤러를 비활성화하면 기존 출력 코루틴을 취소한다.

MainStory도 같은 본문 출력 경로를 사용하되, 기존의 본문 완료 → 클릭 대기 → 다음 노드 이동 정책을 유지했다. 전투·보상의 전역 NodeText 이벤트 API는 유지한다.

## 변경 파일

- UIController: 화면별 본문 출력 및 출력 작업 취소 수명 관리.
- StoryUIController / EventUIController: 숨김 → 본문 → 선택지 표시 순서 적용.
- ChoiceListPresenter: 비활성 라벨을 포함하여 참조 확보.
- NodeChoiceUIValidation: 반복 실행 가능한 Editor 및 Play Mode 검사.

씬·프리팹과 기존 직렬화 필드는 수정하지 않았다.

## 검증 결과

Unity 2021.3.45f2, MainWindow 기준. 수정 전 Console 오류·경고 0개.

- Edit Mode 18개 통과: 활성화 시 숨김, 본문 출력 동안 숨김, 완료 후 텍스트 표시, 반복 표시, 빈 본문, 빈 선택지, 비활성 라벨 검색, 중복 클릭 리스너 방지.
- Play Mode 8개 통과: 임시 Story·Event UI를 동시에 구동하여 진입 직후/타이핑 중 숨김, 각 본문 완료 후 표시, 중간 노드 교체 시 이전 본문 취소, 컴포넌트 비활성화 후 이전 선택지 부활 방지, 재진입, Story 오브젝트 비활성화.
- 검사 중 SaveManager의 저장 이벤트 구독을 해제했다가 복구했으며 실제 게임 진행/저장 함수는 호출하지 않았다.
- 백그라운드에서 실행 시간이 멈춰 이번 실행 동안 Application.runInBackground를 켰다가 원래 false로 복구했다. Play Mode 종료.

실제 GameWindow의 전체 노드 진행과 MainStory 클릭 전환, Android 빌드 및 화면 육안 검사는 이번 검사 범위에 포함하지 않았다.
