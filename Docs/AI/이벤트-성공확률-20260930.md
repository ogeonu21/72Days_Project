# 이벤트 선택지 성공 확률

## 시트 입력

EventChoiceData의 기존 ResultText는 성공 시 본문으로 유지하고 두 열만 추가했다. 별도 SO나 실패 보상 테이블은 만들지 않는다.

| 열 | 용도 | 예시 |
| --- | --- | --- |
| Text | 선택지 버튼 | 운동한다 |
| ResultText | 성공 후 중앙 대화문 | 운동을 통해 힘이 1만큼 증가하였다. |
| SuccessProbability | 0~1 성공 확률 | 0.7 |
| FailureText | 확률 실패 후 중앙 대화문 | 운동에 집중하지 못해 성과를 얻지 못하였다. |

- 1은 항상 성공, 0은 항상 실패이며 두 경우 모두 난수 추첨을 생략한다.
- 1이면 FailureText를 읽거나 필수 검사하지 않는다.
- 1 미만이면 FailureText가 필수다. 범위 밖 값과 잘못된 숫자는 가져오기를 거부한다.
- 확률 셀이 비어 있으면 기존 호환성을 위해 1로 처리한다. 새 열의 헤더는 있어야 한다.
- 기존 55개 선택지는 성공률 1, 실패 문구 공백으로 유지했다. 실제 실패 확률은 원하는 선택지에만 설정한다.
- 시트 변경 후 기존 DataImporter 가져오기 절차로 EventDefinition에 반영한다.
- 아이템 드롭 확률과 선택지의 성공 확률은 별개다.

## 실행 규칙

1. 선택지 조건과 실행 가능 여부를 확인한다.
2. 확률 판정은 한 번만 한다.
3. 성공하면 기존 비용·보상·퀘스트 처리를 실행하고 ResultText를 타이핑한 뒤 클릭을 기다린다. 기존 성공 노드 이동 규칙은 유지한다.
4. 확률 실패면 비용, 골드 감소, 보상, 퀘스트 진행을 적용하지 않는다. FailureText를 타이핑하고 클릭을 기다린 뒤 현재 이벤트의 선택지를 다시 표시한다.
5. Repeatable=false이면 확률 실패도 시도 완료로 기록·저장되어 재시도할 수 없다. Repeatable=true이면 재시도할 수 있다.
6. 조건 불충족이나 실행 오류는 확률 실패와 구분한다. 실패 대화문 대신 기존 결과 로그로 안내한다.

EventResult 계열의 기존 RewardResult에 chanceFailed 플래그를 추가하여 성공, 확률 실패, 실행 오류를 구분한다. 결과 로그와 중앙 대화문은 별도로 유지한다.

## 변경 파일

- EventDefinition: 선택지 확률·실패 문구 및 확률 판정.
- EventDefinitionValidator: 확률 범위와 실패 문구 검증.
- EventSheetData / DataImporter.Events: 신규 열 매핑, 빈 확률 기본값 처리.
- RewardResult / EventManager: 확률 실패 구분 및 보상 이전 분기.
- EventUIRouter: 성공·실패 대화문 선택 및 클릭 대기.
- EventProbabilityValidation: Tools > Validation > Event Probability 검사 추가.

## 검증 범위

- Unity Edit Mode 확률·경계값·유효성·가져오기 파싱 검사 14개 통과.
- 검사 시 Unity Console 오류 0개.
- 원격 시트의 신규 헤더와 기존 55개 선택지의 성공률 1을 재확인했다.
- Play Mode 동작 및 실제 저장 파일을 사용하는 통합 검증은 실행하지 않았다.
- 기존 결과 로그 줄바꿈 동작과 관련된 검사 불일치는 이번 확률 변경 범위에서 수정하지 않았다.
