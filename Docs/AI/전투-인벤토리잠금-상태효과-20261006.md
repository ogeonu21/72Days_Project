# 전투 인벤토리 잠금과 상태효과 표시

## 적용 동작

- 전투 노드 진입 안내부터 종료 결과 안내까지 인벤토리를 열 수 없다.
- 인벤토리 버튼 클릭 시 기존 `EventResultLog`에 **전투 중에는 사용할 수 없습니다.** 를 출력한다. 기존 로그의 0.2초 간격·3초 페이드 처리를 그대로 사용한다.
- 차단된 클릭은 시간 배율을 변경하지 않는다. 인벤토리가 열린 상태에서 전투 노드로 바뀌면 닫고 시간 배율을 복원한다.
- 남아 있는 슬롯/장착/사용/버리기/상세 능력치 콜백도 차단한다.
- 전투 선택지의 **아이템 사용**은 기존처럼 가능하다. 인벤토리 창만 막으며 전투 행동 규칙은 변경하지 않았다.

## 상태효과 UI

플레이어와 적의 이름표 오른쪽에 작은 아이콘과 `x남은턴`을 표시한다.

| 효과 | 아이콘 | 적용 직후 표시 |
| --- | --- | --- |
| 공격력 감소 | 주황색 검·하향 화살표 | x3 |
| 회피율 감소 | 하늘색 회피 궤적·하향 화살표 | x3 |
| 출혈 | 붉은 핏방울 | x2 |

- 표시 숫자는 중첩 수가 아니라 기존 `Character.EffectTurn`의 실제 남은 카운트다.
- 기존 전투는 다음 라운드 시작에서 `CountEffect()`를 호출한다. 기존 효과 지속시간·피해량·능력치 계산은 바꾸지 않았다.
- 턴 감소, 재적용, 만료, `EffectReset`, 캐릭터 재초기화에 맞춰 갱신한다. 0이면 숨긴다.
- 효과 3개를 한 번 생성해서 재사용한다. 매 프레임 상태를 검색하지 않고 `EffectsChanged` 알림을 구독한다.
- 표시 개수만큼 이름 오른쪽 여백을 확보한다. 긴 이름은 말줄임 처리하여 아이콘과 겹치지 않도록 했다.
- 아이콘은 uGUI 도형으로 그리므로 추가 이미지, Addressables, 폰트 특수문자 설정이 필요 없다.

## 구현 위치 / 설정

- `UIManager.cs`: 인벤토리 진입 차단, 전투 노드 상태 추적, 결과 로그 연결.
- `InventoryUI.cs`: 직접 활성화와 남은 클릭 콜백 방어.
- `Character.cs`, `CharacterEffect.cs`: 읽기 전용 턴 조회와 변경 알림.
- `CharacterEffectsUI.cs`: 이름표 옆 자동 UI 생성과 구독 관리.
- `CharacterEffectIcon.cs`: 효과별 도형 렌더링.
- `CombatInventoryEffectsValidation.cs`: Edit Mode 검사 및 프리팹 미리보기 생성.

현재 Player/Enemy 프리팹의 `nameText`를 사용해 실행 중 자동 구성한다. 씬/프리팹을 다시 저장하거나 버튼을 재연결할 필요 없다. `UIManager.resultLog`는 선택적 Inspector 연결이며, 비어 있으면 활성 결과 로그를 찾아 캐시한다. 현재 GameWindow의 `SubUIGroup/EventLogArea`가 활성 상태인 것을 확인했다.

Node/Item/Character SO, 구글 시트, 저장 형식은 변경하지 않았다.

## 검증

- Unity Edit Mode 신규 기능 검사 **43개 통과**.
- 기존 전투 선택지 **26개**, StatsChanged UI **11개** 통과: 총 **80개**.
- 실제 Player/Enemy 프리팹을 격리된 미리보기 씬에 복제하여 이름·HP·세 효과 아이콘·턴 숫자의 화면 배치를 확인했다.
- 컴파일 오류 없음. 실제 저장 파일이나 사용자 씬을 저장하지 않았다.
- Play Mode 실제 전투 클릭 검증 및 기기별 화면 검증은 수행하지 않았다.
