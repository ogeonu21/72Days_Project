# 프로젝트 폴더와 파일 안내

2026-09-30 정리 후 파일 목록 기준. 에디터 도구와 UI 코드 26개를 역할별 하위 폴더로 이동했다. 각 스크립트와 기존 .meta 내용은 그대로 유지했으며 실행 로직은 변경하지 않았다.

## 1. 직접 수정하는 영역

| 위치 | 역할 |
| --- | --- |
| Assets/Script | 직접 작성한 런타임 코드 |
| Assets/Editor | 시트 가져오기·검사·UI 구성 도구 |
| Assets/Scenes | MainWindow, GameWindow, EndingCredit 씬 |
| Assets/Resources | 노드·아이템·캐릭터·이벤트 콘텐츠 데이터 |
| Assets/Prefabs | 프리팹 보관 위치 |
| Assets/Sprite | 스프라이트 리소스 |
| Assets/AddressableAssetsData | Addressables 그룹과 설정 |
| Docs/AI | 설계·사용법·작업 기록·시트 스냅샷 |
| Tools | PowerShell 보조 도구 |

빌드 씬 순서는 MainWindow → GameWindow → EndingCredit로 등록되어 있다. 실제 플레이의 노드 진행 순서와는 별개다.

### 기능을 수정할 때 같이 볼 파일

아래 경로는 `Assets/Script/` 기준이다. 책임 요약은 파일 배치와 관련 코드 확인에 기반하며 전체 실행 검증을 의미하지 않는다.

| 기능 | 먼저 볼 파일 | 함께 볼 위치 |
| --- | --- | --- |
| 게임 시작·세션 | GameManager.cs | Func_System/Function/StartManager.cs |
| 저장·복원 | Func_System/Function/SaveManager.cs | SaveGameData.cs, Character/Player/PlayerData.cs |
| 노드 이동 | Main_System/Management/NodeManager.cs | NodeRunner.cs, UI_System/Common/NodeScreenRouter.cs |
| 전투 | Main_System/Combat/CombatManager.cs | CombatRules.cs, UI_Control/Combat |
| 캐릭터·능력치 | Data_System/Data/Character/Character.cs | Stats.cs, Player/Player.cs, Enemy/Enemy.cs |
| 장비·인벤토리 | Main_System/Inventory/InventoryManager.cs | Data_System/Data/Character/Player/EquipmentData.cs, UI_System/Inventory/InventoryUI.cs |
| 아이템 유형 | Data_System/Data/Item/ItemData.cs | ItemBase 아래 장비·소모품 클래스 |
| 이벤트 설정 | Data_System/Data/Event/EventDefinition.cs | EventDefinitionValidator.cs |
| 이벤트 실행·조건 | Main_System/Event/Base/EventManager.cs | EventChoiceEvaluator.cs, EventProgress.cs |
| 보상 적용 | Main_System/Event/Base/RewardService.cs | Data_System/Data/Reward/Reward.cs |
| 결과 문구·로그 | UI_System/UI_Control/Event/EventUIRouter.cs | EventResultLog.cs, Func_System/Function_Effect/TypewriterEffect.cs |
| 상세 능력치 화면 | UI_System/Character/PlayerStatsDetailsUI.cs | UI_System/Common/UIViews.cs, UI_System/Common/UIManager.cs |

## 3. 에디터 도구

`Assets/Editor/` 아래에서 Importing(가져오기), Validation(검증), Setup(UI 구성)으로 나눴다.

| 분류 | 파일 |
| --- | --- |
| Importing: 시트 가져오기 | DataImporter.cs, DataImporter.Events.cs |
| Importing: 시트 형식·파싱 | EventSheetData.cs, SheetJson.cs |
| 데이터 검사 | GameDataValidator.cs, DataImporterValidation.cs |
| 이벤트 검사 | EventSystemValidation.cs, EventChoiceConditionValidation.cs, EventProbabilityValidation.cs, EventResultPresentationValidation.cs |
| 전투·캐릭터 검사 | CombatAttackValidation.cs, CharacterRefactorValidation.cs, CharacterStatsUIValidation.cs |

| UI 검사 | NodeChoiceUIValidation.cs, PlayerStatsDetailsValidation.cs, MobileUiValidation.cs |

위 표에서 Importing·Setup으로 표시하지 않은 검사 파일은 모두 Validation에 있다.

## 4. 콘텐츠와 외부 의존성

`Assets/Resources/`에는 Characters, Items, Nodes, EventDefinitions, Data, Events 폴더가 있다. 이름이 유사하더라도 `Events`를 불필요한 폴더라고 단정하여 삭제하지 않는다. 참조와 데이터 가져오기 경로를 먼저 조사해야 한다.

다음 영역은 외부 패키지·리소스 또는 생성물로 구분한다.

- ClassicPixelRPGUI, TextMesh Pro: UI 리소스·패키지 영역.
- GooglePlayGames, ExternalDependencyManager, Plugins: 외부 연동·플랫폼 플러그인 영역.
- GeneratedLocalRepo: 의존성 생성 영역. 일반 게임 코드처럼 재배치하지 않는다.
- Library, Temp, Logs, UserSettings, Builds, csproj, sln: 로컬 생성·출력 파일. 현재 `.gitignore`에 관련 제외 규칙이 있다.
- Keystore: 민감한 로컬 서명 자료. 내용 열람·이동·삭제는 이번 정리에서 하지 않았다.

## 5. 이번에 적용한 재배치와 남겨둔 영역

경로 정리와 기능 리팩토링을 분리했다. 이동 전후 26개 스크립트와 26개 .meta의 SHA-256 값이 동일함을 확인했다.

1. **적용:** `Assets/Editor/`를 Importing / Validation / Setup 하위 폴더로 나눴다. 모두 Editor 내부에 유지했다.
2. **적용:** UI_System 루트의 인벤토리·슬롯·아이콘을 Inventory, 상세 능력치 화면을 Character, 화면 관리·안전 영역을 Common으로 묶었다.
3. Data_System 안의 RewardManager·CurrencyManager처럼 실행 로직인 파일은 관련 런타임 관리 영역으로 모으는 안을 검토한다. 폴더명만으로 결함이라고 판단하지 않는다.
4. `Docs/AI/`는 우선 [문서 목록](README.md)으로 찾는다. 실제 이동은 기존 문서 링크·도구의 경로 의존성을 확인한 후 진행한다.
5. Resources 경로·클래스명·네임스페이스는 한꺼번에 바꾸지 않는다. 이동 후 GUID, Inspector 연결, 로드 경로, 가져오기 및 컴파일을 검증한다.

Unity MCP 연결 실패로 에디터 안에서의 컴파일·Inspector 연결 검증은 수행하지 못했다. Unity에서 다시 가져오기가 끝난 후 Console을 확인해야 한다. Play Mode, 씬 저장, 빌드, 캐시 삭제는 수행하지 않았다. 과거 작업 문서에 기록된 경로는 당시 이력으로 유지하며 현재 위치는 이 문서를 기준으로 찾는다.
